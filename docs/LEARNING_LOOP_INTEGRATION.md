# ClimateShield — Learning Loop & Model Governance Integration

## Overview

The **ClimateShield Learning Loop** provides an end-to-end relational lineage and controlled model calibration engine for Ahmedabad Municipal Corporation (AMC). It bridges:
1. **Historical Forecasts**: Risk predictions generated by WBGT, precipitation, and combined multi-hazard engines.
2. **Recommended Interventions**: Candidate municipal actions generated by the ILP Knapsack Optimizer.
3. **Authorized & Executed Actions**: Dispatched field actions requiring explicit human sign-off, tracking actual crew, water, and costs, as well as failure modes.
4. **Verified Civic & Health Outcomes**: Ground-truth surveillance from AMC hospitals, 108 emergency dispatches, and civic helpline CCRS 155303 complaints.
5. **Controlled Parameter Calibration**: Bounded, human-in-the-loop updates to ward vulnerability offsets and intervention efficacy weights.

---

## Safety & Governance Principles

- **Relational Lineage**: Uses deterministic stable identifiers across the decision lifecycle (`pred_...`, `rec_...`, `act_...`, `out_...`, `verif_...`, `eval_...`, `prop_...`, `v1.x.0`).
- **Data Provenance Discipline**: Strictly tags data as `REAL`, `ESTIMATED`, `SIMULATED`, or `UNVERIFIED`. Simulated demo data and incomplete actions are strictly blocked from mutating production model parameters.
- **Privacy & Non-PII**: Ingests only aggregate municipal statistics. Free-text fields are filtered by PII rejection regex (blocking phone numbers, emails, and Aadhaar-like IDs).
- **Human-in-the-Loop Governance**: Production model weights never auto-mutate. Parameter updates are staged as proposals requiring named municipal official authorization.
- **Minimum Evidence Threshold**: Requires $N \ge 3$ verified real observation pairs before generating parameter calibration proposals. Reports `INSUFFICIENT_DATA` when evidence is scarce.
- **Causal Attribution Guardrails**: Distinguishes between correlational before-and-after evaluations and quasi-experimental Difference-in-Differences (DiD) evaluations with comparison control wards.

## REST Endpoints Specification

### 1. Recording Prediction & Action History

#### `POST /api/learning/predictions`
Records a risk forecast with stable ID, risk tier, and provenance metadata.

**Request:**
```json
{
  "ward_id": "W1",
  "hazard_type": "heat",
  "predicted_risk_score": 82.5,
  "risk_category": "CRITICAL",
  "data_source": "Open-Meteo Weather API + ECOSTRESS LST",
  "provenance": "REAL",
  "timestamp": "2026-06-01T14:00:00Z",
  "details": {
    "ambient_temp_c": 44.2,
    "wbgt_c": 32.5
  }
}
```

**Response (HTTP 201):**
```json
{
  "prediction_id": "pred_20260601140000_a1b2c3",
  "ward_id": "W1",
  "ward_name": "Danilimda",
  "timestamp": "2026-06-01T14:00:00+00:00",
  "hazard_type": "heat",
  "predicted_risk_score": 82.5,

  "data_source": "Open-Meteo Weather API + ECOSTRESS LST",
```

## Frontend Learning Loop Dashboard

The frontend is built with **React** and styled with a custom **Dark Glassmorphism Design System** in `frontend/src/index.css`.

### Running Locally

```bash
# Option 1: Run Vite dev server with proxy to backend
cd frontend
npm run dev
# Accessible at http://localhost:5173

# Option 2: Run via FastAPI Backend (serves production build)
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
# Dashboard accessible at http://127.0.0.1:8000/dashboard/
# API Root accessible at http://127.0.0.1:8000/
```

### Dashboard Features

1. **Predicted vs Observed Risk Over Time**: Interactive SVG time-series chart with ward and hazard selectors, displaying real observations vs model predictions, with an informative empty state when no verified outcomes exist.
2. **Intervention History & Status**: Track dispatched interventions, completion/failure status, actual resource expenditures, and update statuses on the fly.
3. **Verified Municipal Outcomes**: Log aggregate non-PII morbidity, mortality, and civic complaint telemetry with provenance tagging.
4. **Multi-Hazard Accuracy Metrics**: Heatwave, pluvial flood, and water shortage precision, recall, MAE, RMSE, and confusion matrices.
5. **Trends & Data Gaps**: Transparency disclosures on sparse ward surveillance, lookback coverage deficits, and causal control limitations.
6. **Proposed Model Updates**: Staged parameter proposals with supporting sample evidence and interactive municipal sign-off / rejection modals.
7. **Model Version Ledger & Rollback**: Complete audit trail of active and archived versions with one-click rollback.
8. **Hackathon Live Demo Controls**: Built-in seed helper to test the dashboard against both populated and empty datasets.
